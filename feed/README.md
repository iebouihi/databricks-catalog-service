# Simulated Databricks feed: catalog product export

> Paths below are relative to the repository root.

Built from a 1,000-product FR sample export. Values that the sample doesn't contain (other markets, price tiers, MDM IDs, attributes) are **synthetic**.

## Grain and principles
- **One row = one product (sellable G-code).** Everything about the product is nested in the same row, so a single row is always internally consistent.
- **Categories come from another pipeline.** Products only carry `category_refs[].category_id`. `category_ref/` is a stand-in for that pipeline, used for orphan checks.
- **Typed nested columns, not a JSON string.** Parquet keeps types, statistics and column pruning, and readers (Spark, DuckDB, parquet-avro) unnest natively.
- **Lists are `array<struct>`, not `map`.** Each entry carries metadata (unit, locale, market) and the order is stable.
- **Money is `decimal(18,4)`, EAN is a `string`** (zero-padded to 13 digits), and timestamps are UTC microseconds.

## Schema (contract `catalog.product` v1.0.0)
```
product_id            string  NOT NULL         G-code, business key
family                struct<family_id, name_fr>
brand                 struct<brand_id, name>
mfr_ref               string
lifecycle_status      string                    ACTIVE | PHASE_OUT | BLOCKED
identifiers           array<struct<type, value, market, source>>         INTERNAL_REF, MFR_REF, MDM_ID, EAN, ERP_xx
category_refs         array<struct<category_id, taxonomy, is_primary>>
texts                 array<struct<locale, name, erp_name, family_name, slug, status>>   status: SOURCE | TRANSLATED | MISSING
attributes            array<struct<code, value_type, value_string, value_number decimal(18,6), value_bool, unit, locale>>
media                 array<struct<asset_id, asset_type, role, url, mime_type, locale, revision_ts, sort_order>>
markets               array<struct<market, status, visible_anonymous, sales_unit, min_order_qty, pack_size,
                                   stock_status, lead_time_days, url,
                                   prices array<struct<price_list, currency, min_qty, unit_price, price_per, valid_from, valid_to>>>>
source_updated_at     timestamp(UTC)
export_id, export_ts  string, timestamp(UTC)  NOT NULL
```
See `samples/sample_product.json` for one complete row.

## Layouts
```
feed/product/export_date=2026-11-27/part-00000-<uuid>-c000.snappy.parquet   (full export, 1,000 rows)
                                                   /part-00001-<uuid>-c000.snappy.parquet
                                                   /_SUCCESS                                  Spark completion marker
feed/product/export_date=2026-11-28/...                                      (995 rows: 5 delisted, 10 PHASE_OUT, 40 price changes)
feed/category_ref/export_date=2026-11-28/...                                 other pipeline (stand-in)
out/delta/product/_delta_log/0...0.json (generated)                                       Delta v0 = day 1
                         00000000000000000001.json                                            Delta v1 = day 2 (what Delta Sharing exposes)
```
Row groups are deliberately small (250 rows) so that partitioning by row group can be tested. In production, aim for files of about 256 MB with row groups of about 128 MB, sorted by `product_id`.

An Iceberg export would contain the same Parquet data files under `data/`, plus `metadata/*.metadata.json` and manifest `.avro` files. The reader side doesn't change.

## Drift fixtures (generated by the script under `out/drift/`, not committed) and expected validator result
| File | Expected result |
|---|---|
| `extra_column.parquet` | Accept, log `SCHEMA_DRIFT_EXTRA` |
| `missing_optional_column.parquet` (no `mfr_ref`) | Accept with default, warn |
| `missing_required_column.parquet` (no `product_id`) | **Reject run** |
| `incompatible_type.parquet` (`export_ts` as string) | **Reject run** |
| `renamed_column.parquet` (`productId`) | **Reject**, unless the contract declares an alias |
| `duplicate_keys.parquet` | Load, dedup in build, `DUPLICATE_KEY` warning |

## Quick inspection with DuckDB
```sql
SELECT m.market, count(*) AS products, sum(len(m.prices)) AS price_rows
FROM 'feed/product/export_date=2026-11-28/*.parquet', UNNEST(markets) t(m)
GROUP BY 1;
```
